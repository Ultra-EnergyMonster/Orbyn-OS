# Licence status — owner decision required

The project owner has not selected a project-wide licence yet. Do not add a generic licence file or claim that the repository is open source merely because it is public. A public repository with no licence generally does not grant the broad permissions that an open-source licence would.

Before publishing significant implementation code, present the owner with the trade-offs among permissive licences (for example, MIT or Apache-2.0), copyleft options (for example, GPL-2.0-or-later), and any dual-licensing or component-specific strategy that may be relevant. Explain patents, contribution rights, redistribution obligations, compatibility components, and third-party dependency licences. Do not provide legal advice as a substitute for a qualified review where one is warranted.

Until decided:

- Track each third-party dependency and its licence.
- Preserve upstream notices and licence files.
- Do not copy source code/assets with unclear provenance.
- Do not imply that unlicensed project code has an open-source grant.
- Record the owner's choice in an ADR and add the exact selected licence text only when authorised.
